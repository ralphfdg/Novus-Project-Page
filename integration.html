API Interaction & External Automations

Technical documentation explaining how external systems interact with the API and backend automations.

1. System Overview

The B.R.I.M. (Barangay Resident Information Management) system is an automated local government platform designed to digitize and streamline barangay operations. Transitioning away from manual logbooks, B.R.I.M. provides a REST API-driven backend to connect residents with barangay officials.

The architecture secures data using Role-Based Access Control (RBAC) via the Spatie package and utilizes UUIDs for primary keys to ensure maximum security against enumeration attacks.

Primary Third-Party Integrations:

  • Make.com: Handles document automation and template mapping.
  • Stripe: Processes online payments for certificates and event registrations.
  • Traccar: Serves as an SMS gateway for emergency dispatching.
  • Open-Meteo API: Fetches live weather data for Angeles City.

2. Authentication Instructions

The B.R.I.M. system secures its primary REST API endpoints using Laravel Sanctum, which provides a robust token-based authentication system.

Any external service or application consuming the secure REST API must include a valid Bearer Token within the authorization header of the HTTP request: 

Authorization: Bearer {your_api_token_here}

For comprehensive details on payload structures, developers can view the full interactive Scribe documentation locally by navigating to the /docs route or clicking the API Documentation link in the navigation.

3. API Usage Examples

The REST API exposes several core endpoints for managing resident data. These endpoints are strictly protected by the Sanctum middleware.

Retrieve Data

  • GET /api/residents — Fetch a complete list of residents.
  • GET /api/residents/{id} — Fetch a specific resident by their UUID.

Create Records

  • POST /api/residents — Requires a valid JSON payload with resident demographic data to instantiate a new record.

Update & Delete

  • PATCH /api/residents/{id} — Update specific attributes of a resident.
  • DELETE /api/residents/{id} — Permanently remove a resident record.

4. Integration Workflow Explanation

B.R.I.M. relies on several orchestrated data flows to handle requests and community events seamlessly.

Payments & Webhooks (Stripe)

When a resident requests a certificate or registers for a paid event, they are redirected to a live Stripe Checkout session. Upon successful payment, Stripe sends a cryptographic webhook to the unauthenticated /api/webhooks/stripe endpoint. The server verifies the signature, updates the database status to "Paid", and triggers an automated email receipt via Mailtrap.

Automated Document Generation (Make.com)

When a barangay Secretary approves a pending document request, the backend immediately triggers an event to Make.com. Make.com captures the JSON payload, maps the fields onto a Google Doc template, creates the official PDF, and securely saves it to Google Drive. Simultaneously, a tracking number is generated and sent via SMS to the resident.

Incident SMS Alerts (Traccar)

When a resident logs a community issue or emergency, the incident is permanently tied to their profile for accountability. The backend then instantly reaches out to the local Traccar SMS gateway over the network, dispatching an emergency text alert directly to active responders or Barangay Tanods.
