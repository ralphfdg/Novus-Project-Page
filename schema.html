Database Schema


Core Entity-Relationship Structure

Below are the core business tables that power the B.R.I.M. system, illustrating how resident data, service requests, and barangay events are linked.

Users Table (users)

Column Name Data Type Description
id CHAR(36) Primary Key (UUID)
name VARCHAR(255) Account holder's full name
email VARCHAR(255) Unique email address for authentication
password VARCHAR(255) Hashed password

Residents Table (residents)

Column Name Data Type Description
id CHAR(36) Primary Key (UUID)
user_idFK CHAR(36) References users.id
first_name / last_name VARCHAR(255) Resident's primary identification
date_of_birth DATE Used for age validation
gender ENUM 'Male', 'Female', 'Other'
civil_status ENUM 'Single', 'Married', 'Widowed', 'Legally Separated'
purok_or_street VARCHAR(255) Local barangay address
residency_status ENUM 'Active', 'Moved', 'Deceased'

Certificate Requests (certificate_requests)

Column Name Data Type Description
id CHAR(36) Primary Key (UUID)
resident_idFK CHAR(36) References residents.id
certificate_type VARCHAR(255) Type of document requested
tracking_number VARCHAR(255) Unique identifier for tracking status
request_status ENUM 'Pending', 'Processing', 'Ready', 'Claimed'
payment_status ENUM 'Unpaid', 'Paid'
stripe_transaction_id VARCHAR(255) Payment gateway reference

Incident Reports (incidents)

Column Name Data Type Description
id CHAR(36) Primary Key (UUID)
resident_idFK CHAR(36) References residents.id (Reporter)
incident_type VARCHAR(255) Category of the incident
location_details VARCHAR(255) Specific location of occurrence
status ENUM 'Pending', 'Under Investigation', 'Resolved'
